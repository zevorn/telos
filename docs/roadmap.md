# Telos Roadmap

端侧与云侧统一的高可信 Agent 运行时。

## 1. 愿景

Telos 是一个用 C 构建的精简、确定性核心，配以"一切皆插件"的扩展体系，
在同一套核心上支撑两种产品形态：

- **Developer Agent**：桌面 / CI 场景的编码助手（TUI 为调试前门）。
- **Edge Agent**：端侧设备助手，两种形态——无 NPU 的 MCU（Zephyr）
  依赖云端模型、联网决策；带 NPU 的 Linux 设备本地推理 1B-10B 模型。
  处理实时感知、自主执行、预测性维护等关键任务。

核心设计约束：**稳定运行数月的无人值守**、**确定性可验证**、
**Linux 与 Zephyr 双平台**、**关键任务领域可信**。

## 3. 核心设计原则

1. **核心 = 纯框架**：核心只保留跨平台共享的生命周期与架构契约
   （Reactor、Registry+Scope、事件序列、Checkpoint 框架、Hook 点
   定义、能力框架），不实现任何业务行为。一切行为都是插件。
2. **Everything is plugin**：设备型号 / 平台差异 = 不同的插件集合。
   同一核心，两种产品；同一核心，Linux 与 Zephyr 各取所需。
3. **模型写数据，不写代码**：Self-evolving 的正确形态是模型生成
   workflow / 技能包数据，由插件化的确定性解释器执行；C 代码变更
   走 OTA，不进运行时。
4. **端云同构**：同一套核心与插件 ABI 同时面向端侧与云侧；
   云侧是端侧的"更大号插件集合"，不是另一套系统。
5. **Workflow 是插件不是核心**：长程任务解释器消费核心提供的
   Task Scope / Checkpoint / Reactor 能力，本身作为插件注册，
   平台按资源情况选择是否加载（Linux 完整版 / Zephyr 精简版）。

## 4. 模型来源：端侧与云端的反直觉分工

| 设备形态 | 资源 | 模型来源 | Telos 集成方式 |
|---|---|---|---|
| MCU（Zephyr） | 无 NPU、KB 级 RAM | **云端模型**（联网） | 网络传输插件 + 云 provider |
| Linux + NPU | 1B-10B 本地可跑 | **本地模型**（localhost API） | provider 插件指向本地 endpoint |
| Linux 桌面/CI | 充足 | 云 API 或本地 | 与上两者同构 |

**核心洞察**：本地 NPU 模型（llama.cpp / MLC 等）以 API 形式暴露
（如 `localhost:8080`），与云端 API 调用方式同构。Telos 的
provider-neutral 请求 / 流式事件协议统一两者——provider 插件只是
endpoint 不同，模型协议、工具、前端完全复用。

**离线自治的重新定义**：
- MCU 设备：断网自治 = 确定性规则 / workflow 执行；
  LLM 决策需要网络，但本地规则引擎照常工作（优雅降级）
- Linux + NPU 设备：真正的离线 LLM 自治（本地推理 + 本地决策闭环）

## 5. 高可信 Harness 设计

这是端侧价值的核心：让 LLM 智力在关键任务上可靠发挥。

### 5.1 确定性执行层
- LLM 只做**决策与规划**，输出结构化指令（workflow / 工具调用）。
- 执行由确定性 C 解释器完成：相同输入 → 相同输出 → 可测试可验证。

### 5.2 双通道校验
- 关键路径（安全联锁、写操作）：LLM 决策 + 规则引擎校验，
  两者一致才放行。规则引擎是普通 C 插件，可独立测试。

### 5.3 任务作用域（Task Scope）
- 每个长程任务开启一个作用域；注册的副作用（资源、注册项、
  订阅、定时器）在任务完成 / 失败 / 取消时一次性精确撤销。
- 这是 Cordis "可逆性"思想在 C 中的落点：任务级回滚，
  不依赖模块热替换。

### 5.4 检查点与恢复
- 每步状态写入 Event Store（环形/Flash），崩溃或 OTA 后
  从最近检查点恢复任务，保证"几个月不停机"的业务连续性。

### 5.5 可靠性基座
- 看门狗 + 心跳：任务与系统健康可观测。
- 能力最小化：每个插件声明所需 capability，运行时强制。
- 内存审计：bounded allocation 规则 + sanitizer 门禁。

## 6. 核心与插件边界

### 判定原则
核心只保留"没有它，两个平台就无法共享正确性语义"的东西；
一切能力差异进插件。

### 必须进核心（跨平台共享的不变式）
| 模块 | 理由 |
|---|---|
| Reactor | 确定性事件循环，两平台调度语义一致 |
| Registry + Task Scope | 生命周期骨架：事务注册、作用域 dispose |
| 事件序列 | 单调序号排序（session 已实现），恢复时从 Store 重建 last_sequence |
| Checkpoint 框架 | 快照/恢复的框架契约（后端是插件） |
| Hook 点契约（ABI） | "框架"本身的定义 |
| Capability / 策略框架 | 能力声明与强制的统一语义 |
| 无堆路径纪律 | Zephyr 硬约束，核心必须带头 |

### 必须插件化（平台 / 场景差异）
| 插件 | Linux 形态 | Zephyr 形态 |
|---|---|---|
| 前端 | 完整 TUI | 精简 Shell |
| 长程任务 | Workflow 解释器（完整） | 精简 workflow / 无 |
| 工具 | bash / posix 工具集 | GPIO / 传感器工具 |
| 存储 | JSONL / 内存 | Ring / Flash 环形 |
| 传输 | curl / 网络 | SPI / Flash / 本地总线 |
| 模型后端 | 云 API / 本地 NPU API | 云 API（无 NPU，联网调用） |
| 规则引擎（双通道） | 完整规则集 | 关键安全规则子集 |

### Hook 点设计原则
- Hook **少而深**：每个扩展点解决一类平台差异，不设浅包装
- Hook 是 ABI 契约：核心只定义接口与生命周期语义，
  实现完全在插件侧
- 静态注册表（Zephyr）与动态加载（Linux dlopen）
  共用同一套描述符结构，差异只在装载方式



## 7. 长程任务：Workflow DSL

```
模型生成 Workflow（结构化数据，非代码）
  → 插件化的确定性 C 解释器执行（状态机）
  → 每步检查点持久化
  → 失败/取消 → Task Scope dispose → 状态回滚
  → 崩溃/OTA → 从检查点恢复
```

Workflow DSL 是长程规划、无人值守自治、以及自进化能力的共同载体。
解释器本身是插件（Linux 完整版 / Zephyr 精简版），
消费核心提供的 Task Scope / Checkpoint / Reactor 能力。

## 8. Self-evolving 落地形态

```text
云侧大模型：生成 workflow / 技能包（数据）
  → 离线验证（schema 校验 + 沙箱回放）
  → OTA 下发（签名固件/数据分区）
  → 端侧解释器加载执行
```

端侧不加载任意代码；只接受经签名、校验的数据化技能包。

## 9. 端侧与云侧分工

| 能力 | 端侧（Edge Agent） | 云侧（可选） |
|---|---|---|
| 实时决策/执行 | ✅ 主责 | — |
| 离线自治 | ✅ | — |
| 数据主权 | ✅ 数据不出域 | — |
| 全局优化/跨设备学习 | — | ✅ |
| 大模型推理 | Linux+NPU 本地 1B-10B；MCU 无本地推理 | ✅（>10B） |
| 生成新技能包/workflow | — | ✅（离线验证后下发） |
| 设备群管理/遥测汇聚 | 上报摘要 | ✅ |

## 10. 阶段路线

### Phase 1 — 稳定核心（当前）
- 完成内存审计与 `docs/security-audit.md` 门禁
- 72h soak test：连续运行监控内存/句柄/状态
- sanitizer + coverage 全绿；TUI 达到日常可用
- **出口条件**：Developer Agent 可日常使用，核心零泄漏

### Phase 2 — 可逆性与恢复
- `telos_task_scope`：任务作用域 + dispose 语义 + 测试
- 检查点/恢复：Event Store 快照、崩溃恢复路径
- **出口条件**：长程任务中途崩溃可恢复到最近检查点

### Phase 3 — 长程任务
- Workflow DSL 定义 + C 解释器 + 回滚/恢复
- 模型生成 workflow 的 schema 与离线验证
- **出口条件**：端侧无人值守跑通一个完整巡检/维护流程

### Phase 4 — 端侧部署与高可信
- 模型 provider 插件：Linux+NPU 本地推理（量化+流式）、Zephyr 云模型
- 双通道校验 + 看门狗/心跳 + 优雅降级
- A/B 分区 OTA + MCUboot；Zephyr 无堆分配路径
- **出口条件**：端侧设备稳定运行数月，OTA 升级不中断任务

### Phase 5 — 自进化闭环
- 云侧技能包生成流水线 → OTA 下发 → 端侧加载
- 设备经验回传（脱敏摘要）→ 迭代技能包
- **出口条件**：设备群技能包持续演进，无需现场运维

## 11. 关键设计决策（待定项）

| 决策 | 选项 | 建议 |
|---|---|---|
| Workflow DSL 格式 | JSON / TOML / 自研二进制 | 先 JSON（可调试），关键路径转二进制 |
| 检查点频率 | 每步 / 定时 / 事件驱动 | 每步 + 定时兜底 |
| Task Scope 粒度 | 每任务 / 每会话 / 每代注册 | 每任务为主，会话级聚合 |
| OTA 传输 | 整包 / 差分包 | 先整包，后差分 |
| 端侧模型上下文 | 环形压缩 vs 摘要 | 环形压缩 + 会话检查点 |
